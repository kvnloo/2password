## Feature mapping and conformance gaps

| Feature | RLP v1 clause | Source commit(s) | Status | Gap against passd reference |
| --- | --- | --- | --- | --- |
| Typed policy | Capability → request → approval §1 | fork #1 `10b4748 a75e50b b5459a8 fb8e036` | Policy draft | passd stores versioned definitions with a backing selector, allowed methods/path and header rules, plus authenticated scopes and host ceilings. The draft checks caller-supplied tuples and includes reveal. |
| Request binding | Capability → request → approval §2 | upstream #6 `2275541 6b92175`, #8 `19a041c 073452a` | Descriptor only | 2password binds exact normalized HTTPS URL including query via fingerprint, raw reference, GET, header and prefix. passd binds capability ID/version and validated method/path to an agent/request digest, rejects query and decoded traversal, records a reason and deduplicates pending requests. |
| Human decision | Capability → request → approval §3, GAP-2 | upstream #9 `93243bc`, #10 `a3411f8 9979520` | CLI draft | TTY and desktop metadata authentication gate direct minting. passd has an independently authorized reviewer, immutable pending request, approve/deny transitions and approval digest. Same-user local CLI access and direct op custody bypass are unresolved. |
| Lease and bounds | Capability → request → approval §§2–3 | upstream #8 `9e77325 a953518`, #9 `93243bc` | Store and policy draft | Store UUID identifies a local database principal and the caller passes a lease ID. passd scopes to an authenticated agent and selects a matching lease. The CLI defaults to 10m/1 use and permits 1s–1h and 1–10 uses. passd uses 60s–24h and 1–100, with approval constrained by the proposed budget and TTL. RLP defaults to 300s and shares the request ID with the lease. |
| State transition | Consume → inject → receipt (atomic use accounting) | upstream #8 `9e77325 a953518`, #9 `1d6a9e3` | Atomic SQL claim prototype | Both guard live budget at mutation time. Align selection and failure semantics. 2password checks DNS before claim, then burns the claim on failed read, rotation or send. passd's capability path claims before target DNS validation and source resolution. |
| Custody freshness | Version and digest representation, Consume → inject → receipt (field binding), GAP-1 | upstream #9 `93243bc 1d6a9e3 03b1218` | Metadata prototype | 2password compares item ID plus numeric revision before and after reading; unrelated edits may invalidate and alias/account resolution needs binding. RLP stored credentials use a keyed field-value version and a capability version. Item-level revisions alone fail the `metadata-change.json` vector, which preserves authority after unrelated edits. Its live Proton selector version describes source identity, so it does not prove value rotation. |
| Network execution | Consume → inject → receipt (target and HTTP response), GAP-3–5 | upstream #6 `2275541 ddb4d07 92bd6de`, #10 `b8f9f02 a3411f8` | Private executor prototype | 2password pins a vetted public address, limits to GET/443 and two headers, withholds response headers/body, and reports byte and echo counts. passd resolves and validates then uses urllib, accepts capability-configured methods, headers and bodies, and returns allowlisted response headers and body after literal redaction. Both refuse redirect following. The RLP response clause requires filtered headers and body, while GAP-4 requires protection from upstream-controlled disclosure. Resolve that conflict with W1 before claiming production response conformance. DNS pinning addresses GAP-5. |
| Decisions and receipts | Consume → inject → receipt (audit), GAP-6 | fork #1 `10b4748 a75e50b`, upstream #10 `a3411f8` | Durable audit missing | Draft receipts and status JSON are not an event trail. passd records attributable decisions and invocations. 2password lease receipts/store carry raw references and a plain lease ID, and the display destination omits the query. RLP requires admin-only encrypted audit and identifies missing terminal outcomes as GAP-6. Define safe review and audit projections separately. |
| Disable authority | Revocation and failures | upstream #8 `9e77325 a953518`, #10 `a3411f8` | Local revoke prototype | passd can revoke access and agent identity centrally. Local revocation gates future claims by ID. Define owner authorization, scope and already-claimed in-flight behavior. |
| Cross-platform wording | Operational support for approval and custody | upstream #7 `cd2c911 6b19666 0ea5bb4` | Independent quick win | No protocol effect. Use credential-store wording across Keychain and DPAPI. |

The legacy `read`, `env resolve`, `run` and `env run` routes remain in the PR stack. Keep the RLP agent identity away from those paths and from direct vault credentials, desktop approval and the state database. The standalone #6 executor is reusable internal plumbing; its unleased CLI is outside the integration plan.
